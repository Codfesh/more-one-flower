# 再采一朵 · Demo

《再采一朵》的可玩 Demo（Canvas 2D，零依赖，单文件游戏逻辑）。
**双击 `index.html` 即可开始游戏**（无需服务器、无需构建、无需联网）。

> 核心决策：**再采一朵，还是现在回巢？**

![gameplay](screenshot-gameplay.png)

> 📄 **要给面试官 / 评审看的版本**：见 [`策划案.md`](策划案.md) —— 定位、设计思路、完整数值表、
> 迭代史（每版发现的问题与验证数据）、演示动线建议。
> 本 README 是工程侧的开发记录（逐轮改了什么、为什么、怎么验证）。

## 一、怎么玩

**冬季模式**：一局 = 连续过冬。每个冬天 **120 秒**，蜂巢蜜仓要囤够**配额**才能活下来。

- **囤够配额 = 立刻过冬**，自动进入下一个冬天（不需要手动结算；小结会自动走完，点击 / 空格可跳过）
- 每个冬天开始时会弹一次三选一蜂巢强化，配额也随之提高
- 时间到没囤够 → 蜂巢饿死；命耗尽 → 也算结算。活过更多冬天 = 新纪录

游戏内操作：

| 输入 | 行为 |
|---|---|
| 鼠标 / 手指移动 | 蜜蜂跟随光标（也支持 WASD / 方向键） |
| 靠近花朵 | 自动采蜜 **0.5 秒**，期间不能移动（按空格冲刺可中断） |
| 飞进蜂巢 80px | 自动卸蜜，每 20 蜜 = 10 分 + 1 经验，同时计入蜜仓 |
| `空格` | 过载冲刺：400 px/s 持续 0.5s，消耗 **30 蜜 + 1 次**（回巢恢复 1 次，上限 3） |
| `Q` | 舍蜜逃生：丢 50% 蜜，立刻回到空载速度；蜜滴落在地上 5 秒内可回头捡 |
| `E` | **蜜香诱饵**（需强化）：吸引 400px 内巡逻 / 警觉的黄蜂 4.5 秒（冷却 12s） |
| `P` / `Esc` | 暂停　`R` 重开　`M` 静音 |
| `1` `2` `3` | 升级时选择强化（也可直接点卡片） |

主菜单只有两项：**开始过冬** / **操作说明**（↑↓ 选择，回车确认）。

手机上会自动出现「冲刺 / 舍蜜 / 诱饵」触屏按钮。

> 开发用：`?mode=endless` 或 `api.startRun('endless')` 仍可进入**无尽刷分模式**（保留在代码里，用于对比手感与 A/B 调参，不作为玩家入口）。

## 二、第七轮迭代：自动过冬 + 主菜单 + 配额 500

### 1. 囤够配额立即过冬（不再手动结算）

原来囤够后要按 `F` 收工，现在**囤够的同一帧就自动结束冬天**：小结停留 2.4 秒（带进度条倒计时）
→ 自动进入下一个冬天 → 弹一次三选一强化。点击 / 空格可以跳过小结，但**什么都不按也能一路打下去**。
"提前完成奖励（剩余时间 ×3 分）"保留，只是从"玩家的选择"变成了"打得快就自动多拿分"。

顺手补了一条设计保障：**背上没卸完的蜜会带进新冬天**（不会因为自动结算而凭空消失），并且有断言覆盖。

### 2. 简单主菜单（替掉"说明文档式"的开局页）

原来开局整页都是说明文字，确实又长又像文档。现在：

```
                再采一朵
        冬季 1　配额 500 蜜　时限 120 秒

        ┌──────────────┐
        │   开始过冬    │     ← ↑↓ 选择 / 回车 / 点击
        ├──────────────┤
        │   操作说明    │
        └──────────────┘

        最佳　活过 4 个冬天　6820 分
             ↑ ↓ 选择　回车确认
```

操作说明挪到独立一页（9 行 键位 → 说明），主菜单只留标题、一行上下文、两个按钮、一行记录。

### 3. 首冬配额 700 → **500**

实测（`test/winter.mjs`，机器人）：

| 冬天 | 配额 | 平均通关时间 | 占时限 |
|---|---|---|---|
| 1 | 500 | **57 秒** | 47% |
| 2 | 610 | **90 秒** | 75% |

第 3 个冬天起机器人开始被黄蜂带走（4 局里 0 次饿死、4 次被抓死）—— 现在的失败原因主要是黄蜂，配额是节奏器。


## 三、第六轮迭代：单一冬季模式 + 配额校准 + UI 排版系统

### 1. 只保留冬季模式

删掉标题页的两个模式卡片，直接进入冬季模式（开局一行说明 + 最佳记录），减少一层选择成本。
无尽模式保留为隐藏入口（按 `2` / `?mode=endless`），因为它是调平衡时的对照基准。

### 2. 配额从"太松"改到"真的会卡住"

先做了量化校准（`test/winter.mjs`：让机器人以"囤够就收工"的最快方式过冬，测每个冬天的实际通关时间），实测结果：

| 版本 | 首冬配额 | 首冬通关时间 | 结论 |
|---|---|---|---|
| 改前 | 220 | **17.9 秒**（120 秒里只用 15%） | 你说的"不难"完全成立 |
| 中间版 | 780 / +260 | 67 秒 → 但第 2 冬就撞墙（799/1040 饿死） | 步进太陡 |
| **现在** | **700 / +110** | 首冬 **61 秒**，第二冬 **107 秒**（89% 时限） | 首冬是热身，第二冬起真会卡 |

配套改了两个结构性问题：**回巢数按冬天重置**（每个冬天约 14 趟，不重置的话第一个冬天就冲到"极限"阶段）、
**跨冬只保留一半的动态难度加成**（否则第二个冬天直接被动态难度压死）。
每个冬天额外给 `WINTER_RAMP = 4` 的等效回巢起点，作为跨冬的长期抬升。

### 3. UI 排版系统（"字一多就出框"的普遍性修复）

这是我这边的系统性缺陷：之前所有文字都是**固定字号 + 单行**画出来的，字一长就必然出框。现在建了一套排版层：

| 工具 | 作用 |
|---|---|
| `wrapLines(s, maxW, size, weight)` | 按实测宽度逐字符折行（中英混排准），优先在空格 / 标点处断行 |
| `textBlock(...)` | 折行 + 超出行数自动缩字号（最低 60%），支持居中 / 垂直居中，返回占用高度 |
| `fitSize` / `textFit` | 单行文本自动缩到指定宽度内 |
| `textRow(...)` | 一行多个文本块，整体放不下就缩字号 |
| **`fitWarnings`** | **任何"为了塞进框而缩字号 / 截断"都会记一笔**，浏览器自检断言这份清单为空 |

已改造的位置：升级卡片（名称 + 描述 + 标签）、标题页全部文字、HUD 状态行、威胁状态栏、操作提示、
冬季目标面板、横幅（自动换行 + 自适应高度）、结算界面所有行与说明、过冬界面说明。

验证方式也补上了：新增 `api.measureCards()` 布局探针，用**和卡片完全相同的排版参数**检查全部 11 个强化的
名称 / 描述 / 标签是否放得下 —— 现在实测 11 张卡全部通过（诱饵描述折 3 行 308/336px，过载蜜囊折 2 行 331/336px，
名称全部保持 40px 未被缩号）。


## 四、第五轮迭代：两个模式 + 目标感（第六轮已收敛为单一冬季模式）

**问题**：一局只有"死"这一个结局、分数没有出口、"贪"没有被逼的理由 —— 核心决策成立，但缺一个能让它产生后果、并在某时刻结出结果的**容器**。

**改法**：做成两个模式，把"结构"和"刷分"分开。

### 冬季模式：把"贪"变成不得不贪

- 每个冬天 **120 秒**，蜂巢蜜仓要囤够 **配额**（首冬 220，每冬 +90）。
- 囤够 → 蜂巢活下来，进入下一个冬天（配额更高，黄蜂季同步推进），并且**每次过冬给一次三选一强化**。
- 囤够后可以按 `F` **提前收工**：剩余每 1 秒 = **+3 分** —— 于是"早收工少冒险"和"继续贪多赚分"变成一个真实的取舍。
- 时间到没囤够 → **蜂巢饿死**（结算显示"活过 N 个冬天"）；命耗尽 → 也是结算。
- 目标从第一秒就明确（进度条 + 倒计时），而且**保守策略会自动被淘汰**：内环刷一趟只赚 100 蜜，倒计时会告诉你不够 —— 不再需要用黄蜂去惩罚保守。

### 无尽模式：把分数本身当成目标

- **实时评级预测**：状态栏常驻 `评级 A`，按当前平均每趟载蜜率与存活时间实时计算，让"再稳一点就是 S"变成过程目标（原来是结算才看得到）。
- **个人最佳记录**（localStorage）：右上角常驻 `最佳 3200`，标题页两张卡片各显示自己的最佳记录。`file://` 下若禁用 localStorage 会静默降级，不影响游戏。

### 技能系统：三个"改变玩法"的新强化

| 强化 | 效果 | 为什么这么设计 |
|---|---|---|
| **蜜香诱饵**（主动，`E`） | 丢下诱饵，400px 内**巡逻/警觉**的黄蜂被吸引 4.5 秒（追击中的不受影响），冷却 12s | 第一个**主动**技能：清走廊、抢金花、脱身，玩家自己决定什么时候用 |
| **逆风冲刺**（改造冲刺） | 冲刺**不再消耗蜜**、只耗次数，且冲刺途中**免疫抓取** | 把冲刺从"逃生工具"变成"精准穿越"：贴着黄蜂飞过去成为可操作的高光 |
| **过载蜜囊**（改变玩法） | 允许超载 30%，**超出容量的蜜回巢按 3 倍价值结算**，但过载时更慢（最多再 -20%） | 把"贪"做成一个显式开关；实测一趟 130 蜜得 190 分 vs 普通 100 蜜得 140 分（+36%），值得咬牙 |

删除（第四轮）：侦察蜂（地图本身已显示方向，没有存在价值）。

## 五、第四轮迭代：删除项

按试玩反馈删除的三项：

- **侦察蜂技能**：删除。理由是地图本身已经显示花朵方向，这个技能没有存在价值 —— 空出的技能位给了第五轮的三个新强化。
- **负载嗡鸣音效**：**整条删除**（不是调轻）。现在只剩威胁警报与一次性提示音；"满载警告"也从刺耳方波换成柔和的下行双音。
  负载的反馈改由视觉承担：蜜蜂变琥珀色、蜜囊膨胀、蜜囊条、满载红色闪烁环、屏幕橙色暗角。
- **连采蜜线**：删除。连采数字、里程碑横幅与蜜蜂上方的进度条保留。

## 六、第三轮迭代：音效 / HUD / 威胁分布 / 金花经济

### 1. 采集负重音效（已在第四轮整条删除）

第三轮曾把"持续锯齿低频"改成"振翅节拍"，但试玩反馈仍是"音效本身不舒服"，所以第四轮直接删除，不再保留任何负载持续音。

### 2. HUD 文字重叠（已在第六轮升级为通用排版系统）

"阶段"与"时间"原来是硬编码 x 坐标（340 / 500 右对齐），阶段名一变长就压在一起 —— 这是"字一多就出框"最早的信号。
当时用 `textRow()`（按实测宽度排布）修了，但**只修了那一行**；第六轮把它升级成通用排版层
（`wrapLines` / `textBlock` / `textFit` / `textRow` + `fitWarnings` 告警），并把所有"文字长度不固定"的位置都改用它。

### 3. 黄蜂贴着蜂巢：把威胁推到外围

**原问题**：巡逻锚点会落在蜂巢附近，而"跟随玩家活动区"的权重又跟着你（你常在内环刷花，黄蜂就堵内环），
导致出门 / 回家被堵、外环反而安全 —— 风险梯度是反的。

**改法**：新增四个"空间闸门"：

| 常量 | 作用 |
|---|---|
| `PATROL_MIN_R = 420` | 巡逻锚点不进入蜂巢 420px 内，出门与回家都有跑道 |
| `GUARD_MIN_R = 300` | 只守中 / 外环与金花，锚点紧贴花朵（60~150px），内环留作喘息 |
| `FOLLOW_MIN_R = 480` | 只有你深入外围，黄蜂才会往你那边压 |
| `WASP_CFG.hiveAvoid 100→170` | 黄蜂绕开蜂巢的范围翻倍 |

**按玩家位置统计的实测结果**（这才是体验）：

| 你所在的区域 | 时间占比 | 被追击 | 平均最近黄蜂 |
|---|---|---|---|
| 蜂巢 250px 内 | 47.7% | **2.4%** | 403 px |
| 中环 250–450 | 30.6% | **7.8%** | 326 px |
| 外环 450px 外 | 21.6% | **9.2%** | 344 px |

出门 / 回家明显轻松了，而"往外跑"现在是全图最容易被追的地方。

### 4. 金花值得跑了：金蜜 + 溢出转化 + 金光招蜂

**原问题**：金花只是"蜜量 ×3"，但**蜜囊容量才是瓶颈** —— 装满后多采的蜜全部溢出，
于是"跑很远拿金花"永远不如"就近摘几朵小花"，玩家没有理由出远门。

**改法（三层一起）**：

1. **金蜜（不占负重）**：金花额外给 **40 金蜜**，独立于蜜囊、不减速你；回巢按 **每 20 金蜜 = 30 分 + 3 经验**结算（普通蜜的 3 倍）。
2. **溢出转化**：蜜囊装不下的部分按 **75% 折成金蜜** —— 金花在任何载重下都不亏，彻底消除"白跑"。
3. **金光招蜂**：金花出现时，**700px 内巡逻中的黄蜂会被金光拉过去**（持续 5.5 秒，头顶金色菱形标记）。
   于是金花同时是**最高收益**和**最高风险**：金光柱一亮，你就得决定"现在冲还是等它们散开"。
4. 金花一次性得分 100 → **200**，被抓会连同金蜜一起丢光（跑远路的风险是真的）。

实测（机器人）金蜜 23~30/分钟，单朵金花约值 **290~350 分**，而一趟内环满囊约 150 分。

## 七、第二轮迭代：黄蜂警戒、密度与反馈

### 1. 黄蜂警戒：从"距离驱动"改成"状态驱动"

**原问题**：警戒圈画的是固定 34px 装饰圆，而真实侦测半径是 200px（警觉）/ 160px（追击）——**圈在骗人**；
音效则是"黄蜂进入 400px 就持续嗡鸣"，实测 **41.8% 的时间**都在响，且正在巡逻（根本没发现你）的黄蜂也会触发心跳声。

**改法**：
- 四档威胁 **安全 / 巡逻邻近 / 警觉 / 追击**，只有**警觉与追击才出声**（实测出声时间占比 8.9%）；分档用"上升快、回落慢"做迟滞，边界不闪断。
- 画面上画出**真实侦测半径**：警觉＝黄色虚线圆（180/200px），追击＝红色圆（150/160px）+ 指向你的虚线 + 屏幕边缘红色箭头；巡逻黄蜂**不画圈**。
- 黄蜂头顶加状态徽标：`!` 黄＝警觉、`!` 红＝追击、`?` 青＝正前往最后目击点搜寻、金色菱形＝被金花吸引。
- 事件音效节流（0.5s / 1.6s），6 只黄蜂不会各叫一次。

### 2. 难度：不是"黄蜂太少"，是"黄蜂站错位置"

**原问题**：地图 2800×2000、视野只能看到 37%，6 只黄蜂均匀游荡时**最近邻期望距离 ≈ 483px**（实测中位数 464px），
而追击触发半径只有 120px —— 必须主动凑到"典型距离的 26%"才会被追，于是空路随便走。

**改法（数量仍是 1 + 回巢/3、上限 6）**：资源化巡逻（守中 / 外环高价值花、回巢走廊、玩家活动区）、
地图缩到 2300×1650、追击阈值 120 → 160、新增 `investigate`（丢失目标后飞向最后目击点搜寻，脱离要靠断视线）、
**同时追击上限 2 只**、新黄蜂不在玩家 600px 内刷新且有 2.5 秒入场预告。

| 指标 | 改前 | 改后 |
|---|---|---|
| 最近黄蜂距离中位数 | 464 px | **290~320 px** |
| 时间占比"黄蜂在 400px 内" | 41.8% | **66~73%** |
| 遭遇（进入追击） | 2.67 次/分钟 | **5.7~7.9 次/分钟** |
| 死亡 | 0.91 次/分钟 | **0.30~0.47 次/分钟** |
| 采蜜收益 | 44 蜜/分钟 | **102~194 蜜/分钟** |

### 3. 蜂巢内静音

蜂巢 80px 是"绝对安全区"，音频层原来完全没读这个状态。现在进入安全区：威胁音效 0.25 秒内淡出归零 + 暗角消失，
给一次温暖的上行音 + "安全区 · 卸蜜"提示；HUD 威胁栏显示"蜂巢内 · 绝对安全（音效已静音）"。

### 4. 采蜜正反馈

| 新增 | 说明 |
|---|---|
| **连采音阶递增** | 连采第 N 朵，"叮"按五声音阶升高，连采 5+ 再叠一层高音 |
| **连采进度条** | 贴在蜜蜂上方：`连采 ×N` + 到下一个里程碑（3/5/8/12）的进度，里程碑有爆点 / 震屏 / 横幅 |
| **贪心奖励** | **被追击时还敢采蜜 → "胆大包天 +10~50"**（越近越赚）+ 金色屏边闪光 + 专属音效，结算统计"贪心采蜜 N 次" |

### 附：一个必须改的数值 —— 升级曲线

跑平衡测量时发现：**20 分钟里机器人一次都没升级**。按策划案的"每 20 蜜 = 1 经验、每 100 经验 = 1 级"，一级需要 2000 蜜；
实测收益约 100 蜜/分钟 —— **一局 3~5 分钟根本看不到升级**，整个升级系统等于不存在。

改为递增曲线 `25 / 35 / 45 / 55 …` 经验，并把"安全回巢"计入经验（每趟 +2）。
现在约 **1 次升级 / 100 秒**，一局 4~5 分钟能拿到 3~4 次强化。

## 八、已实现的策划案机制

- **速度公式**严格按设计：`速度 = 空载300 × (1 - 载蜜率 × 0.5)` → 0% = 300、50% = 225、100% = 150 px/s（有自动化断言）。
- **花朵三环**：内环白 20 蜜 / 中环黄 30 / 外环红 50 / 金花 60 + 金蜜 / 毒花 -1 命。存在 15 秒，5 秒后刷新，同屏 `5 + 回巢/3`，上限 12。
- **黄蜂 AI**：巡逻(150) → 警觉(180) → 追击(220~260+) → 搜寻 → 3 秒冷却；蜂巢回避、个体互让、边界内活动；
  首次登场教学（0–2 次只巡逻 / 3–5 次 180px 察觉 / 6+ 正常）。
- **难度六阶段**：教学 / 初压（毒花）/ 成长（外环 + 花蜜雨）/ 贪心（金花翻倍）/ 高压 / 极限（6 只黄蜂），
  另有动态难度（连续 3 次安全回巢黄蜂提速、连续 2 次被抓降速缩范围、蜜囊常满黄蜂更频繁、常空载回巢花朵蜜量 +20%）。
- **蜂巢与升级**：安全区 80px、防御圈 150→250px（黄蜂减速 50%→65%）、强化三选一。
- **掩护与逃生**：3~5 处花丛（黄蜂失去目标 2 秒）、舍蜜逃生（蜜滴 0.8 秒后才可捡回）。
- **计分与结算**：连采 3/5/8/12、满囊 +50 / 完美 +100、金花 +200、存活 30 秒 +10、未满 80% 回巢卸蜜效率 -20%；
  结算展示 9 项数据 + S/A/B/C 评级。
- **音效**：全部由 WebAudio 实时合成（无音频文件）。

## 十、已知限制 / 下一步

- **配额曲线还需要真人确认**：机器人实测首冬 57 秒 / 第二冬 90 秒（时限 120），第 3 个冬天起被黄蜂带走；
  4 局里有 2 局在首冬就被抓死 —— 说明现在**黄蜂才是主要的失败原因**，配额是节奏器。
  你玩几局告诉我"卡在第几冬、是饿死还是被抓死"，我用 `WINTER_QUOTA0` / `WINTER_QUOTA_STEP` / `WINTER_RAMP` 精调。
- **未做的候选**：技能流派化发牌（蜜囊流 / 速度流 / 生存流）、迷雾（花朵方向只显示已探索区域）、
  每冬解锁新机制（金花潮 / 双蜂编队 / 暴风雨）、花蜜折射 / 破风 / 假死主动版。
- **"花朵离黄蜂多远"这个指标仍是反的**（内环 233 / 中环 294 / 外环 477px），但**玩家实际体验的梯度已经正过来了**
  （蜂巢附近被追 2.4%、中环 7.8%、外环 9.2%）。不一致的原因是：全场只有 6 只黄蜂、花朵有 8~12 朵，
  未被"守"的花天然离黄蜂很远，所以"某朵花离黄蜂多远"不等于"我去那里有多危险"。
- **音量与音色需要真人耳朵确认**：无头浏览器跑不出声音（本轮已按反馈删掉全部负载音，只剩威胁警报）。
- 美术仍是几何图形灰盒；音效资源化、微信小游戏移植（需替换输入与音频层）未做。
